1 The stack

Every layer of the app and why it's there.

Frontend
Vanilla HTML + CSS + JS

No framework. Faster to ship, easier to debug, no build step for the WebView.

Mobile shell
Capacitor 8 (Android)

Wraps the web app as an installable APK. Same code runs on phone + browser.

Backend
Node 22 + Express 4

REST + Server-Sent Events. Streams reels back to the client as the AI generates them.

AI brain
Google Gemini 2.5 Flash

Reads the document → returns structured JSON of reels, quiz, voice picks. Also generates the per-reel background image.

Voice
3-provider TTS chain

Gemini TTS → Microsoft Edge TTS → Google Translate TTS. Falls through whenever one fails. (Details ↓)

Database
PostgreSQL on Neon

Users, subjects, chapters, saved reels. Asset bytes (image / audio) stored in BYTEA columns so Render's ephemeral disk wipes don't lose anything.

Auth
JWT + bcryptjs

Sign-up / sign-in with email + password. Token stays in localStorage for 30 days.

Hosting
Render (free tier)

Auto-deploys from git push origin main in ~90 sec. Free dyno sleeps after 15 min idle.

CI / APK
GitHub Actions

Every push triggers a Capacitor + Gradle build. Sideloadable APK lands as an artifact ~2 min later.

Why streaming? Generating 10 reels takes ~30 s end-to-end. Instead of waiting, the server emits each reel over Server-Sent Events as it appears in the JSON stream — so you're watching the first reel within ~6 s of tapping Generate, while the rest still build in the background.

3 The voice fallback chain

No single TTS provider is reliable enough. So we cascade through three — first one that returns audio wins.

1
Gemini 2.5 Flash Preview TTS
Best quality, follows the narration's language natively (Arabic → Arabic voice, English → English voice). Has a hard 10 RPM limit, so the chain falls through on rate-limit errors.
2
Microsoft Edge TTS
Free neural voices with a per-language voice map — ar-EG-Salma for Arabic, en-US-Aria for English, plus 9 more. Used when Gemini is exhausted or unavailable.
3
Google Translate TTS
Unofficial endpoint, lower quality but extremely reliable. Last-resort so voice always plays. Splits long narration into ≤180-char chunks since the endpoint has a length cap.
Arabic was broken until we threaded a language hint from client to server. Edge TTS hardcoded English voices regardless of narration language; Google Translate TTS hardcoded tl=en. Both now pick the right voice from a per-language map. There's also a Unicode-block sniffer on the server as a safety net.

5 The journey — every change, in order

From the state I inherited to today, in plain English.

Voice · Multi-language

Restored Gemini TTS as the primary provider

The chain had been simplified to Edge → Google Translate only. Put Gemini back at the top — it delivers the best quality and follows narration language natively. Now: Gemini → Edge → GTranslate.

server.js ttsOneSegment()
Voice · Arabic fix

Made every TTS layer language-aware

Built per-language voice maps for Edge TTS (Arabic, Spanish, French, German, Italian, Portuguese, Japanese, Korean, Hindi, Chinese). Added tl=<lang> to Google Translate TTS. The client now passes settings.language to /api/tts, and the server auto-detects Arabic from Unicode block if the hint is missing.

EDGE_VOICE_BY_LANG GTTS_LANG_MAP detectLanguageFromText()
Voice · Browser fallback

Fixed device-voice fallback for Arabic narration

The browser's SpeechSynthesis fallback was using navigator.language — so Arabic narration with an English UI still picked an English voice. Now it uses the narration's own language to look up a matching device voice.

browserSpeakReel()
UX · Less to read

Simplified the upload screen

Cut 11 chip rows down to 2 visible by default (Language + Style toggle). Removed the hero subtitle. Trimmed the drop zone copy. Made the Generate button bigger and added a soft shadow. Trimmed the narration language picker to English + Arabic only. Folded everything else (Vibe, Look, Length, Pace, Quiz, Voice…) into a single "Style ▾" disclosure.

public/index.html public/styles.css
Visual · Backdrop

Added a soft aurora gradient behind the upload screen

Three radial-gradient blobs (pink top-left, blue top-right, amber bottom) so the screen never feels flat. Pure CSS, no images, weaker opacity for light mode.

#upload-screen.active
Bug fix · Light mode

Made the light theme actually readable

The Style pill, paste-text button, profile name, profile email, library tab labels, sign-out icon, and the "+ New subject" form container were all hardcoded white-on-white in light mode. Each got an ink-toned override.

Bug fix · RTL

Stopped reels from flipping English word order in Arabic UI

Added dir="auto" on each caption chunk + reel title. The browser now picks the reading direction from the first strong character in the narration content, not the page's UI direction. English reads L→R even in Arabic UI; Arabic reads R→L even in English UI.

Bug fix · Layout

Generate button no longer hides behind the tab bar

Bumped .upload-card bottom padding from 96 px to max(130, 96 + safe-area) so the S24 gesture nav doesn't tuck the button out of reach.

Captions · Sync

Stopped captions racing ahead of the voice

Two fixes: dropped the 180 ms caption lead to 0 (any anticipation made the gap worse), and added punctuation-pause weight to the word-timing model — trailing ./!/? add 5 virtual chars, ,/; add 3. The lit word now sits on the sentence-end during the pause instead of skipping ahead.

wordWeight() buildTiming()
Glass theme

Fixed the Liquid Glass theme refusing to scroll

The glass theme had align-items: stretch on the upload screen which capped the card at 100 dvh and clipped anything past the fold. Switched back to flex-start and added overflow-y: auto explicitly.

Brand

Rebranded "reels" → "shorts" everywhere user-facing

EN strings, AR strings, fallback HTML — all changed. Code identifiers (CSS classes, dataset attrs, localStorage keys, the com.reelify.app package name) are deliberately left alone so existing user data doesn't break.

Arabic copy

Cleaner Arabic translation

"موضوع" → "مادة" (academic "subject" instead of generic "topic"). "أَفلِت" → "ضع" on the drop zone / hero. Covers every label, toast, empty state, and confirm dialog.

UX trim

Removed the podcast option + "+ New subject" from home

Format + Voice B chip rows gone — the upload screen is calmer. Subject creation lives only in the Library page now. Stale __new state in localStorage auto-clears on load.

Nav

Renamed "Home" → "Generate" in the bottom tab bar

The middle tab actually does generation, so the icon swapped from a house to a plus and the label updated in both EN ("Generate") and AR ("إنشاء").

Identity

New launcher icon

14 SVG concepts presented in a picker page so you could compare side-by-side at 96 px and 48 px. Your pick — graduation cap with a play badge on top and a yellow lightning-bolt tassel on an Instagram-style gradient — was first ported to SVG, then to a real rendered PNG, sized into all five Android densities (mdpi 48 px → xxxhdpi 192 px), and wired into the adaptive icon.

6 Tools I leaned on

Version Control

CI Trigger

Image processing
sharp (Node)

Resized your 1254×1254 logo PNG into the five Android density buckets for the launcher icon in one script.

TTS
msedge-tts npm package

Talks to Microsoft's neural-voice WebSocket — free, no API key, used as the second link in the voice chain.

Hosting & monitoring
curl + /api/version

Polled /api/version after each push to confirm Render had picked up the new commit before testing.
